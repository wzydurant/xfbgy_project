## 一、模块目标概述

本阶段目标是完整实现**六角格地图模块**，涵盖数据结构设计、地图随机生成算法、规则属性计算及 Android 可视化渲染，为后续单位、战斗、ZOC 等模块提供稳定底层支撑。

## 二、数据结构设计

### 2.1 地图全局参数

| 参数 | 类型 | 范围 | 说明 |
|------|------|------|------|
| `mapWidth` (X) | Int | 20 ~ 40 | 列数，用户可设置 |
| `mapHeight` (Y) | Int | 20 ~ 40 | 行数，用户可设置 |
| `gridLayout` | 枚举 | 固定 | 单数行左偏（Offset Coordinates，odd-r） |
| 坐标原点 | — | (0, 0) | 最左下角格子 |

> **坐标系选型建议**：采用 **偏移坐标（Offset Coordinates，odd-r）** 存储，内部运算时转换为 **轴向坐标（Axial Coordinates）**，兼顾直觉与运算便利性。

---

### 2.2 六角格内部属性（HexCell）

```kotlin
data class HexCell(
    val x: Int,                          // 列坐标
    val y: Int,                          // 行坐标
    var terrain: TerrainType,            // 地形枚举
    var units: MutableList<Unit> = mutableListOf(),  // 单位列表（后续模块预留）
    var movementCost: Int = 0,           // 移动力消耗（叠加计算）
    var zoc: Int = 0b000                 // ZOC 位掩码：bit0=阵营1, bit1=阵营2, bit2=阵营3
)
```

**地形枚举（TerrainType）：**

| 枚举值 | 中文名 | 颜色 |
|--------|--------|------|
| `PLAIN` | 平原 | 浅绿色 `#A8D5A2` |
| `FOREST` | 树林 | 深绿色 `#2D6A4F` |
| `HILL` | 山地 | 褐色 `#8B5E3C` |
| `MOUNTAIN` | 高山 | 黑色 `#222222` |
| `URBAN` | 建筑群 | 灰色 `#9E9E9E` |

> **ZOC 设计说明**：使用位掩码（bitmask）方式，支持多阵营同时占据。例如 `0b011` = 阵营1 + 阵营2 同时控制。

---

### 2.3 六角格边缘属性（HexEdge）

每个六角格有 **6 条边**，编号 0~5（顺时针，从顶边开始），每条边独立存储：

```kotlin
data class HexEdge(
    var hasRiver: Boolean = false,       // 是否有河流
    var fortification: FortType = FortType.NONE, // 防御工事等级
    var movementPenalty: Int = 0,        // 移动破坏值（叠加计算）
    var defenseBonus: Int = 0,           // 防御优势等级（叠加计算）
    var defenseConditions: MutableList<String> = mutableListOf(), // 条件防御优势
    var attackBonus: Int = 0,            // 进攻优势等级（叠加计算）
    var attackConditions: MutableList<String> = mutableListOf()   // 条件进攻优势
)
```

**防御工事枚举（FortType）：**

| 枚举值 | 中文名 | 视觉样式 |
|--------|--------|---------|
| `NONE` | 无 | — |
| `FENCE` | 栅栏 | 褐色小叉连线 `x x x` |
| `EARTHWALL` | 土墙 | 灰色小叉连线 |
| `STONEWALL` | 石墙 | 白色小叉连线 |

> **河流一致性规则**：相邻两格共享同一条边，`hasRiver` 状态必须保持逻辑同步（修改其一时自动同步另一格对应边）。

## 三、初始属性计算规则

> 所有整型属性初始值为 **0**，按规则叠加，最终值 = 各来源贡献之和。

### 3.1 地形对格子属性的影响

| 地形 | 移动力消耗 | 所有边移动破坏 | 所有边条件防御优势 | 所有边进攻优势 | 所有边防御优势 |
|------|-----------|--------------|----------------|--------------|--------------|
| 平原 | +1 | — | — | — | — |
| 树林 | +1 | 所有边 +1 | 追加"骑兵""对攻""远射""炮击" | — | — |
| 山地 | +2 | 所有边 +1 | — | 所有边 +1 | 所有边 +1 |
| 高山 | +20 | — | — | — | — |
| 建筑群 | +1 | 所有边 +1 | 追加"骑兵""远射" | — | — |

### 3.2 河流对边属性的影响

对每条 `hasRiver = true` 的边：

- `movementPenalty += 1`
- `defenseBonus += 1`

### 3.3 防御工事对边属性的影响

| 工事类型 | 移动破坏 | 防御优势等级 |
|---------|---------|------------|
| 栅栏 | — | +1 |
| 土墙 | +1 | +2 |
| 石墙 | +1 | +1 |

> 若该边同时有河流，工事效果**依然叠加**（可视化时工事线绘制在河流蓝线内侧）。

### 3.4 叠加顺序

```
Step 1: 地形 → 格子移动力消耗
Step 2: 地形 → 6条边的移动破坏、条件列表、进攻/防御优势
Step 3: 河流 → 有河流的边，叠加河流效果
Step 4: 防御工事 → 有工事的边，叠加工事效果
```

## 四、地图随机生成算法

### 4.1 地形生成

采用**比例随机 + 聚类平滑**策略，避免地形过于破碎：

| 地形 | 目标比例 |
|------|---------|
| 平原 | 40% |
| 树林 | 30% |
| 山地 | 15% |
| 高山 | 5% |
| 建筑群 | 10% |

**算法步骤：**

1. 按比例预分配地形总数。
2. 随机选取种子格，使用 BFS 扩散形成地形团块（控制自然感）。
3. 高山与建筑群：小团块随机散布，建筑群优先不与高山相邻。
4. 建筑群特殊处理：该格 6 条边防御工事随机统一为同一等级（不得为"无"，即从栅栏、土墙、石墙中随机选取一种）。

### 4.2 河流生成

**约束条件：**

- 河流必须形成连通图（不允许孤立河段）。
- 河流至少延伸到地图边缘一个出口。

**算法步骤：**

1. 在地图边缘随机选取 1~3 个出发点（入/出河口）。
2. 使用**随机游走（Random Walk）** 算法，从边缘出发向内蜿蜒前进，形成主干河道。
3. 允许分支（概率约 20%），但须保持与主干相连。
4. 每次标记一条边时，同步标记相邻格的对应共享边，保持河流逻辑一致性。
5. 生成后执行连通性检验，不连通则重新生成。

## 五、ZOC（控制区）接口设计

```kotlin
// 查询某格是否被某阵营控制
fun HexCell.isControlledBy(faction: Int): Boolean {
    return (zoc and (1 shl (faction - 1))) != 0
}

// 标记某格被某阵营控制
fun HexCell.setZOC(faction: Int) {
    zoc = zoc or (1 shl (faction - 1))
}

// 清除某格某阵营的ZOC
fun HexCell.clearZOC(faction: Int) {
    zoc = zoc and (1 shl (faction - 1)).inv()
}
```

## 六、Android 可视化方案

### 6.1 渲染方案选型

推荐使用 **Android Canvas 自定义 View**（或 `SurfaceView`），不依赖第三方游戏引擎，轻量高效。

```
自定义 View（HexMapView）
├── 继承 View / SurfaceView
├── onDraw() 中遍历所有格子绘制
├── 支持 ScaleGestureDetector（缩放）
└── 支持 GestureDetector（拖拽）
```

### 6.2 六角格绘制逻辑

**尺寸参数：**

- 单个六角格外接圆半径 `R`（像素），可随缩放动态调整，建议初始值约 60px。
- 根据 odd-r 偏移坐标计算每格中心点像素坐标：

```kotlin
fun hexToPixel(x: Int, y: Int, R: Float): PointF {
    val colOffset = if (y % 2 == 1) R * sqrt(3f) / 2 else 0f  // 单数行左偏
    val px = x * R * sqrt(3f) + colOffset
    val py = y * R * 1.5f
    return PointF(px, py)
}
```

**绘制内容（每格）：**

1. 填充地形颜色（实心六边形）
2. 绘制边界黑色细线
3. 绘制各边的河流蓝色粗线（若有）
4. 绘制各边的防御工事线（若有，覆盖于河流线内侧）
5. 可选：绘制坐标标签（调试模式，格内显示 `x,y`）

### 6.3 边的方向与绘制映射

| 方向编号 | 中文方向 | 顶点对 |
|---------|---------|-------|
| 0 | 上 | 顶点0 → 顶点1 |
| 1 | 右上 | 顶点1 → 顶点2 |
| 2 | 右下 | 顶点2 → 顶点3 |
| 3 | 下 | 顶点3 → 顶点4 |
| 4 | 左下 | 顶点4 → 顶点5 |
| 5 | 左上 | 顶点5 → 顶点0 |

### 6.4 交互实现

**点击格子：**

- 通过触摸坐标反算格子坐标（像素 → 偏移坐标）。
- 弹出信息面板，展示：地形、移动力消耗、ZOC状态、单位列表（预留）。

**查看边缘属性：**

- 信息面板内提供方向按钮列表（上/右上/右下/下/左下/左上）。
- 用户点击某方向后，展示该边的完整属性：河流、防御工事、移动破坏、防御优势、进攻优势、条件列表。

**缩放 & 拖拽：**

- `ScaleGestureDetector` 实现双指缩放，动态调整 `R` 值（设置最小/最大缩放限制）。
- `GestureDetector.onScroll` 实现单指拖拽，通过 `canvas.translate()` 偏移绘制起点。

## 九、技术风险与注意事项

| 风险点 | 说明 | 建议处理方式 |
|--------|------|------------|
| 河流共享边同步 | 两格共用一边，修改一侧需同步另一侧 | 封装统一的边访问方法，禁止直接写边数组 |
| 大地图性能 | 40×40=1600格，每帧全量绘制可能卡顿 | 仅绘制视口内的格子；使用 dirty rect 优化 |
| 坐标转换精度 | 像素↔格子坐标反算存在浮点误差 | 使用圆形吸附（取最近格中心点）优化点击精度 |
| 建筑群工事一致性 | 生成时需保证6条边工事类型完全相同 | 生成阶段统一随机一次，写入时批量赋值 |
| ZOC 多阵营支持 | 后续战斗模块可能添加阵营 | 位掩码设计预留至少 8 位，支持最多8个阵营 |
