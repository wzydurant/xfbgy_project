## 1. 模块概览与依赖关系

### 1.1 本模块职责

资源点模块是游戏经济系统的核心，负责：

- 从地图数据中**自动识别**资源点位置（不需要手工放置）
- 管理每个资源点的**产出、消耗、储存**
- 维护**装备生产序列**
- 计算**粮食运输路径**（受 ZOC 影响）
- 维护**压制状态**（与单位模块联动）

### 1.2 对第一阶段的依赖

| 依赖项 | 用途 |
|--------|------|
| `HexMapData` / `HexCell` | 读取地形、防御工事、ZOC |
| `EdgeManager` | 查询公共边的工事类型 |
| `MapEvents.OnCellDataChanged` | 监听工事变化，触发资源点重新识别 |
| ZOC 接口 | 粮食运输路径合法性检查 |

### 1.3 向后预留接口

| 接口 | 供哪个模块使用 |
|------|---------------|
| `IResourcePoint.TakeResource()` | 战斗/招募模块取用资源 |
| `IResourcePoint.SetFaction()` | 占领逻辑改变归属 |
| `IResourcePoint.GetSuppressStatus()` | 前端状态展示 |

## 2. 资源点类型与识别逻辑

### 2.1 四种资源点总览

| 类型 | 地形要求 | 工事要求 | 粒度 |
|------|---------|---------|------|
| 村庄 | 建筑群 | 全部6边均为**栅栏** | 每格独立 |
| 城镇 | 建筑群 | 全部6边均为**土墙** | 每格独立 |
| 都市 | 建筑群 | 全部6边均为**石墙**（相邻都市格之间的边除外） | **聚团**共享1个资源点 |
| 马场 | 平原 | 无工事要求 | 每格独立（随机选取） |

> 马场额外约束：所选格不与任何建筑群六角格直接相邻。

### 2.2 聚团（Cluster）识别算法

都市聚团是"相邻且均为建筑群+石墙"的连通分量，使用 **BFS/Flood Fill** 识别：

```csharp
List<List<HexCell>> FindCityClusters(HexMapData map)
{
    var visited = new HashSet<int>(); // cellIndex
    var clusters = new List<List<HexCell>>();

    foreach (var cell in map.cells)
    {
        if (visited.Contains(cell.Index)) continue;
        if (!IsCityCandidate(cell))       continue;

        // BFS 扩展
        var cluster = new List<HexCell>();
        var queue   = new Queue<HexCell>();
        queue.Enqueue(cell);
        visited.Add(cell.Index);

        while (queue.Count > 0)
        {
            var cur = queue.Dequeue();
            cluster.Add(cur);
            foreach (var neighbor in map.GetNeighbors(cur))
            {
                if (!visited.Contains(neighbor.Index) && IsCityCandidate(neighbor))
                {
                    visited.Add(neighbor.Index);
                    queue.Enqueue(neighbor);
                }
            }
        }
        clusters.Add(cluster);
    }
    return clusters;
}

// 判断是否是都市候选格（建筑群 + 所有非都市相邻边均为石墙）
bool IsCityCandidate(HexCell cell)
{
    if (cell.terrain != TerrainType.Building) return false;
    for (int i = 0; i < 6; i++)
    {
        var neighbor = map.GetNeighbor(cell, i);
        bool neighborIsCity = neighbor != null
            && neighbor.terrain == TerrainType.Building
            && IsCityCandidate(neighbor); // 实际实现中避免递归，用预计算标记
        if (!neighborIsCity && cell.edges[i].fortification != FortType.StoneWall)
            return false;
    }
    return true;
}
```

### 2.3 马场选取算法

```
1. 收集所有候选格：地形=平原 且 与任意建筑群格均不相邻
2. 按地图面积计算马场数量（建议：每 200 格 1 个，最少 1 个）
3. 从候选集中**随机均匀采样**，间距不少于 5 格（六角距离），避免扎堆
```

### 2.4 识别触发时机

- 地图随机生成完成后，自动执行一次全图扫描
- 玩家手动修改某格工事后，对受影响范围重新识别

## 4. 资源产出与消耗系统

### 4.1 产出规则汇总

| 类型 | 每回合产出 | 周期产出 | 每回合消耗 |
|------|-----------|---------|-----------|
| 村庄 | 粮食 +5 | 每5回合：人力+1，牛+1 | 无 |
| 城镇 | 粮食 +2 | 每3回合：人力+1，装备点+1 | 无 |
| 都市 | 人力+1，装备点+1 | 无 | 粮食 -1（不足则人力/装备不产出） |
| 马场 | 无 | 每5回合：马+1 | 粮食 -1（不足则马不产出） |

> **装备点（Equipment Points）** 是原始资源，与生产序列消耗的"装备点数"一致，详见第6章。

### 4.2 周期产出实现

用 **回合计数器（round number）** 取模计算，无需额外存储周期计数：

```csharp
void ProducePeriodicOutput(ResourcePoint rp, int roundNumber)
{
    switch (rp.type)
    {
        case Village:
            if (roundNumber % 5 == 0) { rp.manpowerStock++; rp.cattleStock++; }
            break;
        case Town:
            if (roundNumber % 3 == 0) { rp.manpowerStock++; /* +1装备点进入生产结算 */ }
            break;
    }
}
```

### 4.3 产出-消耗结算顺序（单个资源点）

```
1. 检查压制状态 → 若被压制，跳过一切产出/消耗，直接返回
2. 计算本回合粮食产出（村庄+5，城镇+2，都市/马场=0）→ 汇入全局粮食池
3. 粮食供给分配（见第5章）→ 获得 foodReceivedThisRound
4. 检查粮食是否充足：
   - 都市：foodReceived >= 1 → 正常产出；否则人力/装备跳过
   - 马场：foodReceived >= 1 → 正常产出；否则马跳过
5. 执行本回合产出，写入 stock
6. 执行周期产出（取模判断）
7. 执行装备生产序列推进（见第6章）
```

## 5. 粮食供给与运输逻辑

### 5.1 核心规则

- 粮食**不储存**，每回合清零
- 粮食从**村庄/城镇**流向**都市/马场**
- 运输路径上的所有格**不得含有敌方ZOC**
- **无距离上限**，但优先供给距离最近的消耗点

### 5.2 路径合法性定义

"从格A到格B的路径合法"：存在一条格序列 A→…→B，其中每一格的ZOC中**不包含消耗点归属阵营的对立阵营**。

> 实现时简化为：路径经过的格 ZOC 中，不存在任何**非本阵营**的ZOC标记即为合法。  
> （具体对立关系由游戏规则层配置，接口预留）

### 5.3 最短合法路径查询（BFS）

```csharp
int FindDistance(HexMapData map, (int col, int row) from, (int col, int row) to, int faction)
{
    // BFS，边界条件：格的ZOC中含有敌方标记 → 不可通行
    var queue   = new Queue<((int, int) pos, int dist)>();
    var visited = new HashSet<(int, int)>();
    queue.Enqueue((from, 0));
    visited.Add(from);

    while (queue.Count > 0)
    {
        var (pos, dist) = queue.Dequeue();
        if (pos == to) return dist;

        foreach (var neighbor in map.GetNeighbors(pos.col, pos.row))
        {
            var nPos = (neighbor.col, neighbor.row);
            if (visited.Contains(nPos)) continue;
            if (HasEnemyZOC(neighbor, faction)) continue; // 敌方ZOC阻断
            visited.Add(nPos);
            queue.Enqueue((nPos, dist + 1));
        }
    }
    return int.MaxValue; // 不可达
}
```

### 5.4 粮食分配优先级算法

```
每回合结算时：

Step 1：计算所有生产者（未被压制的村庄/城镇）的粮食产出，汇入列表 producers[]
        每个 producer 带 { point, foodAvailable }

Step 2：计算所有消耗者（未被压制的都市/马场）的需求，列表 consumers[]
        每个 consumer 带 { point, foodNeeded=1 }

Step 3：为每个消耗者找到最近的可达生产者（BFS距离）
        生成 (consumer, producer, distance) 三元组列表，按 distance 升序排序

Step 4：贪心分配（优先距离近的）：
        for each (consumer, producer, dist) in sorted list:
            if producer.foodAvailable >= 1 && consumer.foodNeeded > 0:
                分配1单位：producer.foodAvailable -= 1
                          consumer.foodReceivedThisRound += 1
                          consumer.foodNeeded -= 1

Step 5：距离相同时，按 consumer.id 升序（确定性规则）

Step 6：所有粮食清零（producers 的剩余粮食丢弃）
```

> **注意**：一个生产者可以拆分供给多个消耗者（只要产出量足够），上述算法天然支持这一点。

## 6. 装备生产系统

### 6.1 生产序列管理

城镇和都市各自维护一个**有序队列**，玩家可随时修改：

```csharp
void SetProductionQueue(ResourcePoint rp, List<EquipmentType> newList)
{
    // 修改时：进度清零，重新开始
    rp.productionQueue = newList.Select(e => new ProductionItem
    {
        equipType      = e,
        totalRounds    = EquipCost[e],
        progressRounds = 0
    }).ToList();
    rp.currentQueueIndex = 0;
}
```

### 6.2 每回合生产推进

在回合结算的"装备产出"步骤中执行：

```csharp
void AdvanceProduction(ResourcePoint rp)
{
    if (rp.productionQueue == null || rp.productionQueue.Count == 0) return;
    if (rp.currentQueueIndex >= rp.productionQueue.Count)
    {
        // 队列循环（可选：循环或暂停，待确认）
        rp.currentQueueIndex = 0;
    }

    var item = rp.productionQueue[rp.currentQueueIndex];
    item.progressRounds++;

    if (item.progressRounds >= item.totalRounds)
    {
        // 当前项完成，产出装备
        rp.equipStock[item.equipType]++;
        item.progressRounds = 0;
        rp.currentQueueIndex++;

        // 自动开始下一项（下回合继续推进）
    }
}
```

### 6.3 装备点消耗与独立生产的关系

需求中城镇/都市每回合会产出"装备点数"，同时生产序列也消耗装备点。  
**推荐实现方式**：将"装备点"视为中间货币，但**不单独储存**，而是在回合结算时直接驱动生产进度：

```
每回合城镇获得装备点 = 1（每3回合），都市 = 1（每回合）
→ 若本回合有装备点，则生产序列当前项 progressRounds++
→ 装备点消耗完毕，不累积到下回合（或可选择累积，见附录）
```

> ⚠️ 设计决策：装备点是否可累积？需求未明确，方案默认**不累积**（每回合产出即用于推进生产），可选规则见第12章。

## 7. 压制状态系统

### 7.1 压制判定条件

> 若某资源点所在的**所有六角格**内，均**只包含不属于归属阵营的单位**（敌方单位），则进入压制状态。

等价逻辑：

```
isSuppressed = ALL cells in rp.cells satisfy:
    (该格内无己方单位) AND (该格内存在至少一个单位)
```

> 若格内无任何单位，该格不触发压制（需敌方主动占据）。

### 7.2 压制判定实现

```csharp
bool CalculateSuppression(ResourcePoint rp, UnitManager unitMgr)
{
    bool anyEnemyPresent = false;

    foreach (var (col, row) in rp.cells)
    {
        var units = unitMgr.GetUnitsAt(col, row);
        if (units.Count == 0) continue;               // 空格不触发

        bool hasFriendly = units.Any(u => u.faction == rp.faction);
        if (hasFriendly) return false;                // 任一格有己方单位 → 解除压制

        anyEnemyPresent = true;
    }

    return anyEnemyPresent; // 所有格均被敌占（且至少一格有敌方单位）
}
```

### 7.3 压制期间效果

| 效果 | 说明 |
|------|------|
| 无任何产出 | 粮食、人力、装备点、牲畜均不产出 |
| 无粮食消耗 | 不参与粮食分配计算 |
| 生产进度冻结 | `progressRounds` 不推进 |
| 储存不变 | 储存的人力/装备/牲畜维持原值，不被清除 |

### 7.4 压制解除条件

- 该资源点任一格出现归属阵营的单位
- 资源点归属阵营被修改为当前占据方的阵营（占领逻辑）

## 8. 回合结算流水线

回合结算在每回合结束时由 `ResourceManager.ProcessRoundEnd()` 统一执行，严格按顺序：

```
Phase 1：压制计算
  ├─ 遍历所有资源点
  └─ 调用 CalculateSuppression() 更新 isSuppressed

Phase 2：粮食产出汇总
  ├─ 遍历未压制的村庄 → foodPool += 5（per格，per回合）
  └─ 遍历未压制的城镇 → foodPool += 2

Phase 3：粮食分配
  ├─ 构建 (consumer, producer, distance) 三元组
  ├─ BFS计算合法路径距离（排除敌方ZOC）
  └─ 贪心分配，更新 foodReceivedThisRound

Phase 4：消耗点产出
  ├─ 都市：foodReceived >= 1 → manpower+1, equipPoint+1
  └─ 马场：每5回合 且 foodReceived >= 1 → horse+1

Phase 5：生产者周期产出
  ├─ 村庄（每5回合）：manpower+1, cattle+1
  └─ 城镇（每3回合）：manpower+1, equipPoint+1

Phase 6：装备生产推进
  ├─ 城镇：若本回合有equipPoint → AdvanceProduction()
  └─ 都市：若本回合有equipPoint → AdvanceProduction()

Phase 7：粮食清零
  └─ 所有生产者 foodAvailable = 0，消费者 foodReceivedThisRound = 0

Phase 8：事件广播
  └─ 触发 ResourceEvents.OnRoundSettled，通知UI刷新
```

## 12. 附录：设计决策说明

### 12.1 装备点是否可累积？

**需求原文**未明确。两种实现方式对比：

| 方案 | 说明 | 适合场景 |
|------|------|---------|
| **不累积（默认）** | 每回合装备点即用即消，不进入库存 | 经济节奏偏紧凑，不鼓励囤积 |
| **可累积** | 未被生产序列消耗的装备点存入库存，下回合可继续消耗 | 经济节奏灵活，允许策略储备 |

**建议**：先实现"不累积"，后续如需改为"可累积"只需修改 `AdvanceProduction()` 中的装备点判断逻辑。

### 12.2 生产队列是否循环？

需求未说明队列完成后的行为。方案预留配置项：

```csharp
public enum QueueEndBehavior { Stop, Loop }
```

默认 `Loop`（循环），可在游戏设置中调整。

### 12.3 都市聚团只有一个格时是否合法？

按需求，都市聚团边界格的"与相邻都市之间的边不强制石墙"逻辑，如果都市聚团只有1格，则所有6边均为石墙，仍满足识别条件，**合法**。

### 12.4 马场数量建议

需求未规定马场数量。建议公式：

```
马场数量 = max(1, floor(width * height / 200))
```

示例：40×40=1600格 → 8个马场；20×20=400格 → 2个马场。

### 12.5 与第一阶段的建筑群状态字段兼容

第一阶段 `BuildingStatus` 中已有 `Suppressed` 标记。第二阶段的 `isSuppressed` 字段应在回合结算后**回写**到 `HexCell.buildingData.status`，保持两层数据同步：

```csharp
// 回合结算后同步状态到地图数据层
foreach (var rp in cityPoints)
{
    foreach (var (col, row) in rp.cells)
    {
        var cell = map.GetCell(col, row);
        if (rp.isSuppressed)
            cell.buildingData.status |= BuildingStatus.Suppressed;
        else
            cell.buildingData.status &= ~BuildingStatus.Suppressed;
    }
}
```
